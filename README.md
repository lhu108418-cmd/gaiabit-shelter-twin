# GaiaBit Shelter Twin Admin V3 — 場域模型與雙方案比較

## 更新
- 3D 場景更大，依場域尺寸自動取景；左鍵拖曳旋轉、右鍵／Shift 拖曳平移、滾輪縮放，具俯視、重置、縮放按鈕。
- 3D 由「實心方塊」改為樓板、半透明牆與可點選區域；依 2D 實際輸入位置尺寸生成。
- 上傳 JPG/PNG/WEBP 圖面，疊加至 2D 編輯器及 3D 地面；手工定位區域與尺寸。
- 情境實驗室同頁並列「導入前」與「導入後」，可各自調整攝影機、人力、巡檢間隔、AI、誤報、可用率、反應與處置時間、成本。
- 估算結果使用可追溯的簡化公式，避免固定的宣傳百分比。

## 使用
1. GitHub 更新 `index.html`、`config.json`、`README.md`；`schema.sql` 保留原本 stwin_ 資料表，不需再次執行。
2. Vercel 自動部署。
3. 側欄「場域與模型」→「上傳場域圖片」，選擇 PNG/JPG/WEBP。
4. 輸入場域實測寬、深；調整房間的位置與尺寸；切換 3D。
5. 「情境實驗室」填入 Baseline / GaiaBit 方案，逐項比較，匯出 JSON。

## 明確限制
- 這是 L1 示範模型，不具備將任意 PDF／AI／DWG／單張照片自動產生準確 3D 的能力；非圖片格式需先轉檔，請依實測尺寸校正。
- 建立的房間是手動校正資料，不是圖面自動偵測。
- 估算公式為初步參考，未建置完整離散事件模擬 DES、AI 準確率場域校準、防疫路徑／遮蔽視錐運算。
- 頁面狀態目前儲存在瀏覽器 localStorage；上傳的圖面只存在當前分頁，不會同步到 Supabase 或永久保存。
- Supabase SQL 僅作為後續安全資料儲存結構，沒有宣稱前端已完成資料庫連線。
- 正式導入應補入歷史資料、受限動線／專業規範、覆蓋區幾何、設備位置以及不確定性分析。

## 重要估算假設（待驗證）
- 覆蓋 = min(93%, 45m² × 攝影機台數 ÷ 已配置區域面積) × 設備可用率；實際應再扣除遮擋及重疊。
- 發現時間：人工為巡檢間隔的一半，AI 模式為通知延遲／盲區與巡檢共同決定的簡化假設。
- 完整回應 = 發現 + 通報 + 確認 + 移動 + 處置。
- 工作負荷 = (已輸入任務工時 + 事件數 × 平均處置分鐘) / (有效人力 × 每日有效工時 × 60)。
- 模擬輸入不得直接觸發真實設備操作。
